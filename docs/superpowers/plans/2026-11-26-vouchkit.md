# Vouchkit implementation plan

**Goal** Build and publish the four vouchkit crates from the specification supplied in this conversation.

**Architecture** Core owns authenticated wire formats and verification. The offline CLI owns master key custody. The client owns device proof and persisted renewal state. The server owns delegated issuance and serializes seat mutations in SQLite.

- [x] Implement bounded core decoding, signature validation, verification, CRLs, tags and resource sealing. Pin the wire format with fixed vectors.
- [x] Implement the offline CLI, encrypted master key format and locked issuance ledger. Exercise encrypted issuance and cumulative revocation.
- [x] Implement the transport, device key storage and renewal states. Test offline grace, time tracking and CRL rollback.
- [x] Implement the SQLite activation service and its deployment files. Test activation, renewal, concurrent seats, deactivation and revocation over loopback.
- [x] Add fuzz harnesses, CI, documentation and examples. Run package checks and publish the dependency crates before their consumers.

Review covers wire size limits, signed authorization, device proof replay, seat races and revocation/clock rollback.
